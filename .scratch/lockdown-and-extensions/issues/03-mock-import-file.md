# 03: เตรียมข้อมูลสมมติ — ด่านวันที่ และไฟล์นำเข้า

**What to build:** ด่านปฏิเสธวันติดต่อเข้ามาที่เป็นไปไม่ได้ และไฟล์นำเข้าฉบับสมมติที่พร้อมใช้
แทนไฟล์จริง ใบนี้**ยังไม่แตะฐานข้อมูล** จึงตรวจได้โดยไม่เสี่ยงอะไร

ความรุงรังของข้อมูลจริงคือสิ่งที่กฎล้างข้อมูลถูกเขียนมาแก้ ถ้าไฟล์สมมติสะอาดเกินไป
บั๊กที่เคยแก้จะกลับมาโดยไม่มีเทสต์ไหนจับได้ — ข้อนี้สำคัญกว่าความสวยของข้อมูล

**Blocked by:** None (can start immediately)

## ทำเกินที่ใบเขียนไว้ — และทำไม

ใบนี้เขียนให้แทนแค่ชื่อ เบอร์ และชื่อผู้ดูแล แต่สแกนแยกแล้วพบข้อมูลส่วนบุคคลนอกสามช่องนั้น:
ช่องช่วงเวลาให้ติดต่อมีเบอร์ 7 แถว · หมายเหตุมีชื่อนามสกุลของญาติ อำเภอ จังหวัด ไอดีไลน์
และลักษณะที่ระบุตัวคนได้ · ช่องติดตามมีชื่อเล่นเจ้าหน้าที่ (เช่น "ปุ้ยโทร" "ต้นโทร" — ยกตัวอย่างด้วยชื่อสมมติ)
และชื่อคนอื่นปน ถ้าทำตามใบตรงตัว ข้อมูลพวกนี้จะหลุดเข้า git ซึ่งขัดข้อ acceptance ข้อสุดท้ายของใบเอง

รอบแรกลองล้างด้วย regex แล้วตัวตรวจแบบค้นหาข้อมูลจริงผ่านหมด แต่สแกนด้วยตาเจอชื่อกับที่อยู่
ยังอยู่ จึงเปลี่ยนเป็นสร้างสองช่องนี้ใหม่ทั้งช่อง และตรวจแบบ whitelist
(ทุกเซลล์ต้องเป็นข้อความที่สคริปต์ผลิตเอง) — การทดสอบกลายพันธุ์ข้อ 3 ยืนยันว่า
มีแต่ whitelist ที่จับการหลุดแบบนี้ได้

ผลเสีย: ข้อความในหมายเหตุและช่องติดตามไม่ใช่ถ้อยคำจริงของทีมแล้ว ไม่มีกฎนำเข้าข้อไหน
อ่านส่วนนั้น (ตรวจแล้วว่าผลการโทรและวันที่แปลงได้เหมือนเดิมทุกช่อง)
