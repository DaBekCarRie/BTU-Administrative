# 02: ปิดสิทธิ์เฉพาะเจ้าหน้าที่

**What to build:** คนที่ไม่ใช่เจ้าหน้าที่ที่ยังใช้งานอยู่ อ่านข้อมูลของระบบไม่ได้เลย
ไม่ว่าจะเข้าทางหน้าเว็บหรือถือ token ยิงเข้า API ของฐานข้อมูลตรง ๆ

**เร่งด่วนที่สุดในรอบนี้** — ตรวจแล้วว่าวันนี้ `disable_signup` เป็นเท็จและ Google เปิดใช้อยู่
แปลว่าใครก็ได้บนอินเทอร์เน็ตสมัครแล้วอ่านข้อมูลคนกว่าสามพันรายได้ทันที
ทดสอบบนฐานข้อมูลจริงแล้วว่าผู้ที่ล็อกอินแต่ไม่มีแถวเจ้าหน้าที่อ่านได้: คน 3,434 ·
เหตุการณ์ 6,497 · เอกสาร 52 · การชำระเงิน 27

นี่คือการ**รักษา**เจตนาของ ADR-0004 ไม่ใช่ขัด — ADR นั้นห้ามกั้นข้อมูล*ระหว่างเจ้าหน้าที่*
และเขียนไว้เองว่า "ความต่างอยู่ที่คนนอกยังเข้าไม่ได้เลย" ซึ่งปุ่มลงชื่อเข้าใช้ด้วย Google
ทำให้ไม่จริง เจ้าหน้าที่ทุกคนยังเห็นและแก้ข้อมูลได้ทั้งหมดเหมือนเดิม

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] policy ของทุกตารางในสคีมาสาธารณะเปลี่ยนเงื่อนไขจาก "ล็อกอินแล้ว" เป็น
      "เป็นเจ้าหน้าที่ที่ยังใช้งานอยู่" รวมข้อมูลหลัก (คณะ หลักสูตร) และคลังคำตอบ
- [ ] policy ของที่เก็บไฟล์เอกสารรายคนใช้ด่านเดียวกัน
- [ ] หน้าส่งออกรายชื่อเป็นไฟล์มีด่านของตัวเอง ตอบ 403 เมื่อไม่ผ่าน ไม่ใช่ส่งไฟล์ว่าง
      (เป็น route handler จึงไม่วิ่งผ่านด่านที่หน้าจออื่นมี)
- [ ] ไล่ตรวจ route handler ทุกตัวในระบบว่ามีด่านของตัวเอง และบันทึกผลไว้ในใบนี้
- [ ] เพิ่มกฎใน `CLAUDE.md` ว่า route handler ต้องมีด่านของตัวเองเสมอ เพราะไม่ผ่าน layout
- [ ] เจ้าหน้าที่ที่ถูกตั้งเป็นปิดการใช้งาน เสียสิทธิ์อ่านทันที
- [ ] เทสต์ยิง API ตรงด้วยสิทธิ์คนนอกทีม: ได้ศูนย์แถวทุกตารางและทุก view
      และถูกปฏิเสธทุกฟังก์ชันที่เรียกได้
- [ ] เทสต์ผ่านเบราว์เซอร์ด้วยสิทธิ์คนนอกทีม: ถูกเตะออกจากหน้าจอ **และ**
      เปิดหน้าส่งออกไฟล์ไม่ได้ (สองชั้นนี้พังแยกกันได้ ต้องคุมทั้งคู่)
- [ ] เทสต์เดิมที่ยืนยันว่าคนที่ยังไม่ล็อกอินอ่านอะไรไม่ได้ ยังผ่านครบ
- [ ] เขียน ADR "เฉพาะเจ้าหน้าที่จึงอ่านข้อมูลได้" อธิบายว่าทำไมไม่ขัด ADR-0004
      และอ้างอิงถึงกันสองทาง
- [ ] ข้อความสิทธิ์ทั้งหมดใช้คำ **เจ้าหน้าที่** และ **หัวหน้าทีม** ตาม `CONTEXT.md`
      ไม่ใช้คำว่าแอดมิน
