# 01: ตัวตั้งต้นการล็อกอินสามสิทธิ์

**What to build:** ชุดทดสอบเลือกสวมสิทธิ์ได้สามระดับ — หัวหน้าทีม · เจ้าหน้าที่ · คนนอกทีม
(ล็อกอินได้แต่ไม่มีแถวเจ้าหน้าที่) วันนี้มีบัญชีเดียวและเป็นหัวหน้าทีม ทำให้กฎสิทธิ์ใหม่
ทั้งหมดในรอบนี้พิสูจน์ไม่ได้เลย ใบนี้เป็นการทำให้การแก้ง่ายก่อน แล้วค่อยแก้

เป็น seam ใหม่เพียงอันเดียวของรอบนี้ ยังต้องเก็บ session ไว้ใช้ซ้ำเหมือนเดิม
ไม่ให้แต่ละเทสต์ล็อกอินเองจนชน rate limit ของ Supabase Auth

**Blocked by:** None (can start immediately)

**Status:** claimed

- [ ] ตั้ง `SUPABASE_SERVICE_ROLE_KEY` ใน `.env.local` แล้วสคริปต์สร้างบัญชีทดสอบสามบัญชี
      พร้อมยืนยันอีเมลให้เอง รันซ้ำได้โดยไม่สร้างซ้ำ (`mailer_autoconfirm` ปิดอยู่
      จึงสมัครด้วย anon key แล้วใช้งานไม่ได้)
- [ ] บัญชีหัวหน้าทีมมีแถวเจ้าหน้าที่ `role` หัวหน้าทีม · บัญชีเจ้าหน้าที่มีแถว `role` เจ้าหน้าที่
      · บัญชีคนนอกทีม **ไม่มีแถวเจ้าหน้าที่เลย**
- [ ] ชื่อของทั้งสามบัญชีบอกได้ชัดว่าเป็นบัญชีทดสอบ ไม่ปนกับชื่อคนจริง
- [ ] ตัวตั้งต้นเก็บ session แยกสามชุด เทสต์เลือกใช้ได้ทีละชุด
- [ ] เทสต์ที่มีอยู่ทั้งหมดยังผ่านครบโดยไม่ต้องแก้ (ใช้ session หัวหน้าทีมเป็นค่าตั้งต้น)
- [ ] เขียนวิธีตั้งต้นบัญชีทดสอบไว้ให้คนถัดไปทำซ้ำได้
