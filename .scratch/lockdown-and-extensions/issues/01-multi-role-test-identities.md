# 01: ตัวตั้งต้นการล็อกอินสามสิทธิ์

**What to build:** ชุดทดสอบเลือกสวมสิทธิ์ได้สามระดับ — หัวหน้าทีม · เจ้าหน้าที่ · คนนอกทีม
(ล็อกอินได้แต่ไม่มีแถวเจ้าหน้าที่) วันนี้มีบัญชีเดียวและเป็นหัวหน้าทีม ทำให้กฎสิทธิ์ใหม่
ทั้งหมดในรอบนี้พิสูจน์ไม่ได้เลย ใบนี้เป็นการทำให้การแก้ง่ายก่อน แล้วค่อยแก้

เป็น seam ใหม่เพียงอันเดียวของรอบนี้ ยังต้องเก็บ session ไว้ใช้ซ้ำเหมือนเดิม
ไม่ให้แต่ละเทสต์ล็อกอินเองจนชน rate limit ของ Supabase Auth

**Blocked by:** None (can start immediately)

**Status:** done

      พร้อมยืนยันอีเมลให้เอง รันซ้ำได้โดยไม่สร้างซ้ำ (`mailer_autoconfirm` ปิดอยู่
      จึงสมัครด้วย anon key แล้วใช้งานไม่ได้)

      · บัญชีคนนอกทีม **ไม่มีแถวเจ้าหน้าที่เลย**
- [x] ชื่อของทั้งสามบัญชีบอกได้ชัดว่าเป็นบัญชีทดสอบ ไม่ปนกับชื่อคนจริง
- [x] ตัวตั้งต้นเก็บ session แยกสามชุด เทสต์เลือกใช้ได้ทีละชุด

- [x] เขียนวิธีตั้งต้นบัญชีทดสอบไว้ให้คนถัดไปทำซ้ำได้

## ผลการตรวจ

- `npm run e2e:accounts` (`scripts/setup-test-accounts.mts`) ใช้ service role key สร้างบัญชีที่ยืนยันอีเมลแล้ว
  รันสองรอบติดกันได้ผลเท่ากัน ไม่สร้างซ้ำ · รหัสผ่านสุ่มแล้วเขียนลง `.env.local` ไม่พิมพ์ออกจอ
- **หัวหน้าทีมใช้บัญชีทดสอบเดิม** (`E2E_EMAIL`) ไม่เปลี่ยนชื่อแถวเจ้าหน้าที่ เพราะเทสต์เลขบัตรประชาชน
  ยืนยันชื่อผู้เปิดดูด้วยชื่อ "ผู้ใช้ทดสอบ E2E" · เพิ่มใหม่สองบัญชี `e2e-staff@` และ `e2e-outsider@`
- ตรวจกับฐานข้อมูล: บัญชีใหม่ 2 · แถวเจ้าหน้าที่ทดสอบ 2 (admin, staff) · คนนอกไม่มีแถวเจ้าหน้าที่
- `auth.setup.ts` เก็บ session สามชุด · `e2e/identities.ts` ให้เทสต์เลือกสิทธิ์ · `e2e/README.md` วิธีตั้งต้น
- เทสต์เดิมผ่านทั้งหมดโดยไม่ต้องแก้ · ตรวจ: tsc · lint · unit 144 · build · **e2e 131/131**

## บั๊กจริงที่เจอเพราะมีบัญชีคนนอกให้ทดสอบ

**คนที่ล็อกอินได้แต่ไม่ใช่เจ้าหน้าที่ติด redirect วนไม่รู้จบ** หน้าเข้าสู่ระบบส่งทุกคนที่มี session ไป `/queue`
แล้ว layout ส่งกลับมาเพราะไม่ใช่เจ้าหน้าที่ วนจนเบราว์เซอร์ขึ้น ERR_TOO_MANY_REDIRECTS
ทางลงชื่อเข้าใช้ด้วย Google ไม่เจอเพราะ callback สั่งออกจากระบบให้ แต่บัญชีรหัสผ่านที่ไม่มีแถวเจ้าหน้าที่
และเจ้าหน้าที่ที่ถูกปิดใช้งานระหว่างยังมี session จะเจอ · แก้ให้หน้าเข้าสู่ระบบส่งต่อเฉพาะเจ้าหน้าที่
คนที่ไม่มีสิทธิ์เห็นข้อความ "บัญชีนี้ยังไม่ได้รับสิทธิ์เจ้าหน้าที่" พร้อมอีเมลที่ใช้และปุ่มออกจากระบบ
(ข้อความเดิมเขียนว่า "บัญชี Google นี้" ทั้งที่เกิดกับบัญชีรหัสผ่านด้วย)

- คนนอกเรียก `rebuild_person_state` ถูกปฏิเสธ และ `work_board_counts` คืนศูนย์ — เพิ่มในเทสต์ (เดิมขาดสองฟังก์ชัน)
- เจ้าหน้าที่ลบตรงถูกปฏิเสธ**ครบสามที่** รายการ แถวไฟล์ และตัวไฟล์ใน bucket (เดิมทดสอบแค่รายการที่ไม่มีไฟล์)

  ใช้ชื่อแถวที่ขึ้นต้นด้วย "ผู้ใช้ทดสอบ E2E" แยกบัญชีทดสอบ
- หน้าเข้าสู่ระบบไม่กลบ error อื่นใน URL ด้วยข้อความไม่มีสิทธิ์อีก
- เทสต์ลบของหัวหน้าทีมใช้ `signedInClient` แทนการล็อกอินเอง · ลบคอมเมนต์ที่ยังบอกว่ารอใบ 01
