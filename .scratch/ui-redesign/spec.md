# Spec: BTU LMS Admission System - UI/UX Alignment & Responsive Refinement

Status: ready-for-agent

ศัพท์ทั้งหมดในเอกสารนี้ใช้ตาม [CONTEXT.md](../../CONTEXT.md)
การตัดสินใจทางสถาปัตยกรรมอ้างอิงตาม [docs/adr/](../../docs/adr/)

## Problem Statement

ระบบติดตามผู้สนใจและผู้เรียนปัจจุบันทำงานได้ถูกต้องตามฟังก์ชันหลัก (Core 15 รายการ) แต่เมื่อนำไปทดสอบการใช้งานจริงในสถานการณ์ประจำวันของทีม LMS มหาวิทยาลัยกรุงเทพธนบุรี พบข้อจำกัดด้านประสบการณ์ใช้งานและความคล่องตัว 4 ประการ:

1. **การใช้งานบนมือถือ/แท็บเล็ตยังไม่คล่องตัว**: ปัจจุบันเมนูหลักถูกซ่อนบนหน้าจอขนาดเล็ก (`hidden md:flex`) โดยไม่มีแถบนำทางด้านล่าง (Bottom Navigation) หรือ Drawer ทำให้เจ้าหน้าที่ที่ต้องติดตามผู้สมัครผ่านสมาร์ทโฟนขณะอยู่นอกสถานที่เปิดสลับหน้าจอได้ยาก
2. **การบันทึกผลโทรในคิวขัดจังหวะสายตา**: หน้าคิวโทรปัจจุบันใช้ Modal Dialog กลางหน้าจอเพื่อบันทึกผลโทร ซึ่งบดบังข้อมูลแถวอื่นในตาราง และต้องกดหลายขั้นตอนในการเลือกผลโทรและนัดวันถัดไป ทำให้การโทรต่อเนื่องวันละ 30–50 สายช้ากว่าที่ควร
3. **การตรวจเอกสารกระจัดกระจาย**: หน้า `/documents` ปัจจุบันเป็นเพียงตารางสรุปจำนวนผู้ที่เอกสารไม่ครบ เจ้าหน้าที่ต้องคลิกเข้าไปในหน้าแฟ้มประวัติ (`/leads/[id]`) ทีละคนเพื่อดูไฟล์และกดตรวจ ทำให้การตรวจเอกสารรับสมัครช่วง peak period ล่าช้า และการส่งกลับแก้ไขยังใช้กล่องพิมพ์ข้อความอิสระ (`window.prompt`) ทำให้เหตุผลไม่เป็นมาตรฐาน
4. **ความหนาแน่นของตารางข้อมูลไม่เหมาะกับการกวาดสายตา**: ตารางรายชื่อผู้สนใจมีขนาดแถวที่กว้าง ไม่รองรับโหมดกะทัดรัด (Compact density) ไม่มีระบบเลือกทีละหลายรายการ (Bulk selection) และบนมือถือตารางล้นออกนอกจอต้องเลื่อนแนวนอนตลอดเวลา

## Solution

ปรับปรุงโครงสร้างส่วนต่อประสาน (UI/UX Alignment) และความยืดหยุ่นในการแสดงผล (Fully Responsive) ให้ตรงตามแบบที่ผ่านการทดสอบใน Claude Design Prototype (`BTU Administrative.dc.html`):

1. **Responsive App Shell & Bottom Navigation**:
   - เพิ่มแถบนำทางด้านล่างสำหรับมือถือ (Mobile Bottom Bar: คิวโทร, ผู้สนใจ, เอกสาร, เพิ่มเติม) พร้อม Badge แสดงจำนวนงานค้างแบบเรียลไทม์
   - เพิ่ม Drawer แบบเลื่อนเปิดจากด้านข้างสำหรับเปิดเมนูย่อยและออกจากระบบบนมือถือ
   - ปรับปรุงแถบเมนูด้านข้างบนเดสก์ท็อปให้สามารถย่อ-ขยายได้ (Collapsible Sidebar 240px <-> 56px)
2. **Fast Inline Call Logger & Summary Strip บนหน้าคิวโทร (`/queue`)**:
   - ปรับการบันทึกผลโทรบนเดสก์ท็อปให้เป็น Inline Popover ที่เปิดแนบกับแถวในคอลัมน์ขวาสุด ไม่บังแถวอื่นในตาราง
   - บนมือถือเปิดเป็น Bottom Sheet ที่เลื่อนขึ้นมาจากขอบล่าง พร้อมปุ่มผลโทรขนาดใหญ่ 48px ที่แตะได้ด้วยนิ้วเดียว
   - เพิ่มแถบสรุปยอดเรียลไทม์ (Summary Strip: ค้างโทรวันนี้, โทรสำเร็จแล้ว, เลื่อนนัด) และปุ่มเปิด/ปิดกระดานงานค้าง (Workboard Tiles)
   - อัปเดตสถานะของแถวทันทีแบบ Optimistic UI (แถวเปลี่ยนเป็นสีเขียวอ่อน และปุ่มเปลี่ยนเป็น "บันทึกแล้ว · แก้ไข")
3. **โต๊ะตรวจเอกสารแบบรวมศูนย์ (Unified Document Review Desk บน `/documents`)**:
   - ปรับหน้า `/documents` ให้เป็นแบบ Master-Detail Split View:
     - ฝั่งซ้าย: รายชื่อผู้ยื่นเอกสารพร้อมชิปสถานะเอกสารทั้ง 4 ประเภท (`รูปถ่าย`, `วุฒิ`, `บัตรปชช.`, `ทะเบียนบ้าน`) แยกแท็บ `ทั้งหมด`, `รอตรวจสอบ`, `ผ่านแล้ว`, `ต้องส่งใหม่`
     - ฝั่งขวา (Desk): ข้อมูลผู้สมัคร, แถบสลับตรวจเอกสาร 4 หมวด, พื้นที่พรีวิวเอกสารที่เบลอเอกสารอ่อนไหวโดยค่าเริ่มต้นพร้อมปุ่มเปิดดูและป้ายบันทึก Audit Log, และแผงตรวจอนุมัติ/ส่งกลับแก้ไข
   - มีเมนู Dropdown เลือกเหตุผลการส่งกลับแก้ไขที่เป็นมาตรฐาน 5 ข้อ (รูปไม่ชัด อ่านไม่ออก, ขาดหน้าหลัง, ไฟล์ไม่ใช่เอกสารที่ระบุ, ข้อมูลไม่ตรงกับที่แจ้งไว้, เอกสารหมดอายุ)
   - บนมือถือแสดงเป็นรายการการ์ดพร้อมปุ่ม "ตรวจเอกสาร" ที่เปิด Full-height Review Sheet
4. **ความหนาแน่นตารางและการจัดการหลายรายการ (Dense Table & Bulk Actions บน `/leads`)**:
   - รองรับการปรับระยะห่างแถวแบบแน่น (Compact density) พร้อมจัดฟอนต์ตัวเลขให้ตรงหลัก (Tabular numbers)
   - เพิ่ม Checkbox เลือกรายการในตาราง พร้อมแถบเครื่องมือรวมเมื่อมีการเลือก (ส่งออกที่เลือก, เปลี่ยนผู้ดูแล, ยกเลิกการเลือก)
   - บนมือถือแปลงตารางผู้สนใจเป็นการ์ดสัมผัสง่าย พร้อมแถบชิปเลื่อนกรองสถานะติดตามในแนวนอน

## User Stories

### ระบบโครงสร้างและแถบนำทาง (App Shell & Navigation)

1. As a เจ้าหน้าที่ที่ใช้มือถือ, I want มีแถบนำทางด้านล่าง (Bottom Navigation Bar) 4 ปุ่ม (คิวโทร, ผู้สนใจ, เอกสาร, เพิ่มเติม), so that สลับหน้าหลักได้ด้วยนิ้วหัวแม่มือข้างเดียว
2. As a เจ้าหน้าที่ที่ใช้มือถือ, I want เห็นตัวเลขแจ้งเตือนงานค้างสีแดงบนปุ่ม "คิวโทร" และ "เอกสาร" บนแถบด้านล่าง, so that ทราบทันทีว่ามีสายต้องโทรหรือเอกสารต้องตรวจค้างอยู่กี่รายการ
3. As a เจ้าหน้าที่ที่ใช้มือถือ, I want แตะปุ่ม "เพิ่มเติม" หรือปุ่ม Hamburger ด้านบนเพื่อเปิด Drawer เมนูด้านข้าง, so that เข้าถึงหน้าศูนย์สอบพิเศษ คำถามที่พบบ่อย ข้อมูลหลัก และปุ่มออกจากระบบได้
4. As a เจ้าหน้าที่ที่ใช้เดสก์ท็อป, I want กดปุ่มย่อ/ขยาย Sidebar ได้, so that เพิ่มพื้นที่ในการดูตารางข้อมูลเมื่อเปิดบนหน้าจอโน้ตบุ๊กขนาดกะทัดรัด
5. As a เจ้าหน้าที่ที่ใช้เดสก์ท็อป, I want เห็นแถบแสดงชื่อและบทบาทของตนเอง พร้อมอักษรย่อในวงกลมและปุ่มออกจากระบบที่มุมล่างซ้าย, so that ทราบสถานะผู้ใช้งานปัจจุบันตลอดเวลา
6. As a เจ้าหน้าที่, I want ระบบแสดงผลภาษาไทยด้วยฟอนต์ IBM Plex Sans Thai และตัวเลขด้วย IBM Plex Mono แบบ Tabular numbers, so that ตัวเลขในตารางเรียงหลักตรงกันอ่านง่ายสบายตา

### คิวโทรและการบันทึกผลด่วน (Queue & Fast Call Logging)

7. As a เจ้าหน้าที่บนเดสก์ท็อป, I want กดปุ่ม "บันทึกการโทร" แล้วเปิดเป็นกล่อง Popover เล็ก ๆ ติดกับแถวนั้นโดยไม่บดบังทั้งหน้าจอ, so that ยังเห็นข้อมูลแถวอื่นในตารางขณะกำลังบันทึก
8. As a เจ้าหน้าที่บนมือถือ, I want กดปุ่ม "บันทึกการโทร" แล้วเปิดเป็น Bottom Sheet เลื่อนขึ้นมาจากด้านล่าง, so that มีพื้นที่กดปุ่มผลการโทรขนาดใหญ่อย่างน้อย 44–48px แตะสะดวกไม่พลาด
9. As a เจ้าหน้าที่, I want มีปุ่มตัวเลือกผลการโทรด่วน 6 ข้อ (ไม่รับสาย, คุยแล้วสนใจ, คุยแล้วไม่สนใจ, ขอคิดดูก่อน, นัดโทรใหม่, สมัครแล้ว), so that บันทึกผลได้ในคลิกเดียวโดยไม่ต้องพิมพ์เอง
10. As a เจ้าหน้าที่, I want เมื่อเลือกผลที่ต้องโทรซ้ำ ระบบจะแสดงตัวเลือกวันนัดถัดไปแบบลัด (พรุ่งนี้, 3 วัน, 1 สัปดาห์) พร้อมช่องเลือกวันที่เอง, so that ไม่ต้องเปิดปฏิทินเต็มจอเพื่อเลื่อนหาวัน
11. As a เจ้าหน้าที่, I want เมื่อเลือกผลที่เป็นการปิดเคส (คุยแล้วไม่สนใจ หรือ สมัครแล้ว) ระบบจะซ่อนตัวเลือกวันนัดถัดไปอัตโนมัติ, so that ไม่เกิดการใส่วันนัดค้างในเคสที่จบแล้ว
12. As a เจ้าหน้าที่, I want เมื่อกดบันทึกผลโทร แถวนั้นจะเปลี่ยนเป็นสีเขียวอ่อนทันที และปุ่มเปลี่ยนเป็น "บันทึกแล้ว · แก้ไข", so that รู้ว่าสายนี้บันทึกเรียบร้อยแล้วและไม่ต้องกลัวโทรซ้ำ
13. As a เจ้าหน้าที่, I want ระบบแสดงแถบสรุปสถิติด้านบนของคิว (ค้างโทรวันนี้, โทรสำเร็จแล้ว, เลื่อนนัด) ที่ปรับตัวเลขอัตโนมัติทันทีที่บันทึกสาย, so that เห็นความคืบหน้าของงานวันนี้โดยไม่ต้องรีเฟรชหน้า
14. As a เจ้าหน้าที่, I want มีปุ่มเปิด/ปิดกล่องสรุปงานค้าง (Workboard Tiles 4 ช่อง), so that เลือกซ่อนเพื่อประหยัดพื้นที่แนวตั้งได้เมื่อต้องการดูคิวโทรเต็มตา
15. As a เจ้าหน้าที่, I want กรองคิวโทรตามคำค้นหา (ชื่อ/เบอร์), ผู้ดูแล, และคณะ พร้อมปุ่มล้างตัวกรอง, so that หาคนที่ต้องการโทรหาได้อย่างรวดเร็ว
16. As a เจ้าหน้าที่, I want กลุ่มคนที่ "เลยกำหนดแล้ว" แสดงด้านบนสุดด้วยหัวข้อและไอคอนสีแดงชัดเจน, so that โทรหาผู้สมัครที่รอนานเป็นลำดับแรกเสมอ
17. As a เจ้าหน้าที่, I want กดที่เบอร์โทรในแถวแล้วสั่งโทรออกจากโทรศัพท์ได้ทันทีผ่านลิงก์ `tel:`, so that ไม่ต้องคัดลอกเบอร์ไปกดในหน้าจอโทรศัพท์

### โต๊ะตรวจเอกสารแบบรวมศูนย์ (Document Review Desk)

18. As a เจ้าหน้าที่ตรวจเอกสาร, I want เข้าหน้า `/documents` แล้วเห็นหน้าจอ "โต๊ะตรวจเอกสาร" แบบแบ่งสองฝั่ง (Master-Detail) บนเดสก์ท็อป, so that ตรวจเอกสารผู้สมัครต่อเนื่องได้โดยไม่ต้องกดเข้าออกหน้าแฟ้มประวัติทีละคน
19. As a เจ้าหน้าที่, I want มีแท็บตัวกรองด้านบนแบ่งเป็น "ทั้งหมด", "รอตรวจสอบ", "ผ่านแล้ว", "ต้องส่งใหม่" พร้อมตัวเลขจำนวนคน, so that โฟกัสเฉพาะเอกสารที่รอตรวจได้ทันที
20. As a เจ้าหน้าที่, I want เห็นการ์ดรายชื่อผู้สมัครในคอลัมน์ซ้าย พร้อมชิปแสดงสถานะของเอกสารทั้ง 4 ชนิด (`รูปถ่าย`, `วุฒิ`, `บัตรปชช.`, `ทะเบียนบ้าน`) แยกสีชัดเจน, so that รู้ภาพรวมว่าใครขาดเอกสารอะไรบ้างในแวบเดียว
21. As a เจ้าหน้าที่, I want คลิกเลือกผู้สมัครในคอลัมน์ซ้ายแล้วฝั่งขวาแสดงรายละเอียดและเอกสารของคนนั้นทันที, so that สลับตรวจคนถัดไปได้ด้วยการคลิกเพียงครั้งเดียว
22. As a เจ้าหน้าที่, I want สลับดูเอกสาร 4 หมวดของผู้สมัครคนนั้นผ่านแท็บที่มีจุดสถานะสี (เขียว=ผ่าน, เหลือง=รอตรวจ, แดง=ไม่ผ่าน, เทา=ยังไม่ส่ง), so that ตรวจครบทุกหมวดอย่างเป็นระบบ
23. As a เจ้าหน้าที่, I want เอกสารที่เป็นสำเนาบัตรประชาชนและสำเนาทะเบียนบ้านถูกเบลอไว้โดยค่าเริ่มต้น, so that ป้องกันการเปิดเผยข้อมูลอ่อนไหวโดยไม่จำเป็นตามมาตรฐาน PDPA
24. As a เจ้าหน้าที่, I want กดปุ่ม "กดเพื่อดูเอกสารฉบับเต็ม" เพื่อปลดเบลอเอกสาร และระบบแสดงข้อความเตือนว่าการเข้าถึงนี้ถูกบันทึกใน Audit Log, so that รับทราบเงื่อนไขความปลอดภัย
25. As a เจ้าหน้าที่, I want เมื่อปลดเบลอแล้ว มีแถบสีเหลืองแสดงว่า "บันทึกการเปิดดูแล้ว · [ชื่อเจ้าหน้าที่] [วัน/เวลา]", so that ตรวจสอบย้อนหลังได้ชัดเจน
26. As a เจ้าหน้าที่, I want มีปุ่ม "อนุมัติ" สีเขียวที่กดแล้วเอกสารหมวดนั้นเปลี่ยนสถานะเป็นผ่านทันที, so that ดำเนินการตรวจเสร็จในคลิกเดียว
27. As a เจ้าหน้าที่, I want กดปุ่ม "ส่งกลับแก้ไข" แล้วมี Dropdown เหตุผลมาตรฐานให้เลือก (รูปไม่ชัด อ่านไม่ออก, ขาดหน้าหลัง, ไฟล์ไม่ใช่เอกสารที่ระบุ, ข้อมูลไม่ตรงกับที่แจ้งไว้, เอกสารหมดอายุ), so that เหตุผลการปฏิเสธมีความสม่ำเสมอและเข้าใจง่าย
28. As a เจ้าหน้าที่, I want สามารถกรอกข้อความเพิ่มเติมในช่องหมายเหตุถึงผู้สมัครเมื่อส่งกลับแก้ไขได้, so that อธิบายรายละเอียดเฉพาะกรณีให้ผู้สมัครทราบ
29. As a เจ้าหน้าที่บนมือถือ, I want เห็นรายการการ์ดผู้สมัครพร้อมปุ่ม "ตรวจเอกสาร" ที่เปิด Full Sheet สำหรับดูพรีวิวและกดอนุมัติ/ส่งกลับแก้ไข, so that ตรวจเอกสารบนสมาร์ทโฟนได้อย่างราบรื่น

### ตารางผู้สนใจและโหมดกะทัดรัด (Leads Directory & Table Refinement)

30. As a เจ้าหน้าที่, I want ตารางผู้สนใจมี Checkbox ให้เลือกผู้สมัครทีละคน หรือเลือกทั้งหมดในหน้านั้น, so that ทำรายการกับผู้สมัครหลายคนพร้อมกันได้
31. As a เจ้าหน้าที่, I want เมื่อเลือกผู้สมัครอย่างน้อย 1 คน จะมีแถบเครื่องมือแสดงจำนวนที่เลือก พร้อมปุ่ม "ส่งออกที่เลือก", "เปลี่ยนผู้ดูแล", และ "ยกเลิกการเลือก", so that จัดการกลุ่มผู้สมัครได้อย่างรวดเร็ว
32. As a เจ้าหน้าที่, I want คอลัมน์การกระทำ (ปุ่ม "เปิดแฟ้ม") อยู่ติดขอบขวาของตารางแบบ Sticky, so that เลื่อนตารางแนวนอนแล้วยังกดเปิดแฟ้มได้เสมอ
33. As a เจ้าหน้าที่บนมือถือ, I want หน้าผู้สนใจแสดงเป็นรายการการ์ดที่มีข้อมูลสำคัญ (ชื่อ, สถานะ, หลักสูตร, ช่องทางติดต่อ, ผู้ดูแล) แทนการแสดงตารางแนวนอนที่ล้นจอ, so that กวาดสายตาอ่านข้อมูลบนจอมือถือได้ง่าย
34. As a เจ้าหน้าที่บนมือถือ, I want มีแถบชิปสถานะติดตามเลื่อนแนวนอนได้ใต้ช่องค้นหา (ทั้งหมด, ใหม่, กำลังติดตาม, นัดโทรแล้ว, สนใจสมัคร, สมัครแล้ว, ไม่สนใจ, ติดต่อไม่ได้), so that กรองสถานะบนมือถือได้ด้วยการแตะครั้งเดียว

## Implementation Decisions

### การปรับปรุงโมดูลและโครงสร้างส่วนต่อประสาน (UI Modules)

1. **App Shell Module**:
   - ปรับปรุง Layout หลักให้รองรับ State การเปิด/ปิด Mobile Drawer และ State การย่อ/ขยาย Sidebar บนเดสก์ท็อป
   - เพิ่มคอมโพเนนต์ Navigation ล่างสำหรับหน้าจอมือถือ (`MobileBottomNav`) ที่ตรวจสอบพาธปัจจุบันและแสดงผลเฉพาะ viewport `< 768px` (ใช้คลาส responsive ของ Tailwind `md:hidden`)
   - เพิ่มคอมโพเนนต์ Mobile Header ที่มีปุ่มเปิด Drawer ชื่อหน้าปัจจุบัน และข้อมูลผู้ใช้

2. **Queue Module & Inline Popover / Sheet**:
   - ปรับปรุงคอมโพเนนต์บันทึกผลโทรให้รองรับ 2 โหมดการแสดงผล:
     - Desktop (`md:block`): ปรับจาก Dialog modal เป็น Popover anchored บนปุ่มของแต่ละแถว เพื่อไม่ให้บดบังตาราง
     - Mobile (`md:hidden`): ปรับเป็น Bottom Sheet เลื่อนจากขอบล่างตามมาตรฐานโมบายล์
   - ใช้ Outcome Mapping ตามที่กำหนดใน Prototype:
     ```typescript
     // Outcome to follow-up status mapping
     const OUTCOME_STATUS_MAP: Record<CallOutcome, FollowUpStatus> = {
       "ไม่รับสาย": "กำลังติดตาม",
       "คุยแล้วสนใจ": "สนใจสมัคร",
       "คุยแล้วไม่สนใจ": "ไม่สนใจ",
       "ขอคิดดูก่อน": "กำลังติดตาม",
       "นัดโทรใหม่": "นัดโทรแล้ว",
       "สมัครแล้ว": "สมัครแล้ว",
     };
     const IS_CLOSING = (outcome: CallOutcome) =>
       outcome === "คุยแล้วไม่สนใจ" || outcome === "สมัครแล้ว";
     ```
   - เพิ่มแถบสรุปจำนวน (Summary Strip) และเชื่อมโยงกับการนับผลลัพธ์ในคิว

3. **Document Review Desk Module**:
   - ปรับหน้า `/documents` ให้รองรับรูปแบบ Desk (Master-Detail):
     - ซ้าย: รายการผู้ยื่นเอกสารที่กรองตามแท็บสถานะ (`ทั้งหมด`, `รอตรวจสอบ`, `ผ่านแล้ว`, `ต้องส่งใหม่`)
     - ขวา: ส่วนตรวจสอบเอกสาร (Student header, 4 doc tabs, Canvas preview, Action strip)
   - ปรับปรุงโมดูล `reviewDocument` ให้รองรับ Standard Preset Reasons แทนการใช้ `window.prompt`:
     ```typescript
     const REJECT_REASONS = [
       "รูปไม่ชัด อ่านไม่ออก",
       "ขาดหน้าหลัง",
       "ไฟล์ไม่ใช่เอกสารที่ระบุ",
       "ข้อมูลไม่ตรงกับที่แจ้งไว้",
       "เอกสารหมดอายุ",
     ] as const;
     ```
   - พื้นที่พรีวิวเอกสารเชื่อมโยงกับ Action `openDocument` ที่มีอยู่เดิมเพื่อดึง Signed URL และบันทึก `document_access_log` อัตโนมัติเมื่อเป็นเอกสารในกลุ่มอ่อนไหว (`สำเนาบัตรประชาชน`, `สำเนาทะเบียนบ้าน`)

4. **Leads Directory Module**:
   - เพิ่ม Client State สำหรับการเลือกแถว (`selectedIds: Set<string>`) ในหน้า `/leads`
   - เพิ่ม Action Bar เมื่อ `selectedIds.size > 0`
   - เพิ่มมุมมอง Mobile Card View สำรองเมื่อแสดงผลบนจอเล็ก

### สัญญา API และการจัดการข้อมูล (Data & API Contracts)

- ไม่มีการแก้ไข Schema ของฐานข้อมูล หรือเพิ่มตารางใหม่ — ตาราง `people`, `events`, `documents`, `document_access_log`, และ `staff` มีฟิลด์ครบถ้วนรองรับทุกความต้องการแล้ว
- Server Actions เดิม (`logCall`, `reviewDocument`, `openDocument`, `recordUpload`) ถูกนำมาใช้ซ้ำโดยปรับปรุงการส่งพารามิเตอร์ให้รองรับ Form State และคืนค่าผลลัพธ์อย่างรวดเร็ว

## Testing Decisions

### หลักการทดสอบที่ดี
- ทดสอบเฉพาะพฤติกรรมภายนอกที่ผู้ใช้มองเห็น (External behavior) ผ่านจุดเชื่อมต่อสูงสุด ไม่ทดสอบ Implementation details ภายในคอมโพเนนต์
- ทดสอบการแสดงผลและการมีปฏิสัมพันธ์ทั้งในโหมด Desktop Viewport (1280x800) และ Mobile Viewport (390x844)

### ขอบเขตการทดสอบ (Modules to be tested)
1. **Mobile App Shell & Navigation (`e2e/responsive-shell.spec.ts`)**:
   - ทดสอบว่าเมื่อเปิดบนหน้าจอมือถือ แถบ Bottom Navigation แสดงผล และมีปุ่ม คิวโทร, ผู้สนใจ, เอกสาร, เพิ่มเติม
   - ทดสอบว่าการแตะปุ่มเพิ่มเติมจะเปิด Drawer เมนูข้าง และสามารถกดนำทางไปยังหน้าอื่นหรือออกจากระบบได้
   - ทดสอบว่าบนหน้าจอเดสก์ท็อป แถบ Sidebar แสดงผลตามปกติและปุ่ม Bottom Navigation ถูกซ่อน
2. **Queue Fast Call Logging (`e2e/queue.spec.ts`)**:
   - ทดสอบว่าบนเดสก์ท็อป การกดบันทึกผลโทรจะเปิด Popover บนแถว และเลือกผลโทร "คุยแล้วสนใจ" จะทำให้แถวเปลี่ยนสถานะเป็น "สนใจสมัคร" และหายจากคิวตามเงื่อนไข
   - ทดสอบว่าบนมือถือ การกดบันทึกผลโทรจะเปิด Bottom Sheet และมีปุ่มสัมผัสขนาดใหญ่ที่กดได้
   - ทดสอบว่าการบันทึกผลทำให้ Summary Strip ด้านบนอัปเดตตัวเลขทันที
3. **Document Review Desk (`e2e/documents.spec.ts`)**:
   - ทดสอบว่าเข้าหน้า `/documents` แล้วเห็น Desk แบ่งสองฝั่ง มีแท็บสถานะและรายชื่อผู้สมัคร
   - ทดสอบว่าการคลิกเลือกผู้สมัครจะโหลดเอกสารของผู้สมัครคนนั้นมาแสดงในแท็บเอกสาร 4 ประเภท
   - ทดสอบว่าเอกสารอ่อนไหว (สำเนาบัตรประชาชน) มีการเบลอ และเมื่อกด "กดเพื่อดูเอกสารฉบับเต็ม" จะปลดเบลอพร้อมบันทึกประวัติการเปิด
   - ทดสอบการกด "ส่งกลับแก้ไข" แล้วมี Dropdown เหตุผลมาตรฐาน และสามารถกดส่งกลับแก้ไขได้โดยไม่ใช้ `window.prompt`
4. **Leads Multi-selection & Mobile View (`e2e/leads.spec.ts`)**:
   - ทดสอบว่าสามารถติ๊กเลือกผู้สนใจทีละแถว และติ๊ก "เลือกทั้งหมด" ได้ พร้อมแสดงแถบแจ้งจำนวนที่เลือก
   - ทดสอบว่าบนหน้าจอมือถือ รายชื่อผู้สนใจแสดงผลเป็นการ์ดแนวตั้งพร้อมชิปสถานะด้านบน

### การอ้างอิงการทดสอบเดิม (Prior Art)
- เทียบเคียงโครงสร้างการทดสอบจาก `e2e/queue.spec.ts`, `e2e/documents.spec.ts`, `e2e/leads.spec.ts`, และ `e2e/helpers.ts` ที่ใช้ `uniqueName` และการจัดการ session ล็อกอินผ่าน Playwright Storage State

## Out of Scope

- การเปลี่ยนฐานข้อมูลหรือเพิ่มตารางใหม่ใน Supabase
- การเพิ่มระบบ Notification ภายนอก เช่น Push Notification บนมือถือ หรือ LINE Webhook แจ้งเตือน
- การแก้ไขฟังก์ชันคำนวณเครดิตดรอป หรือระบบลงทะเบียนศูนย์สอบพิเศษ (มีสเปกและชุดทดสอบของตนเองแล้วในรอบแรก)
- การสร้าง Native Mobile App (iOS/Android) — ในรอบนี้เป็นการปรับปรุง Web Responsive (PWA-ready) เท่านั้น
