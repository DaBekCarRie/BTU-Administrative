## ผลการตรวจ

- บันทึกผลโทรจบใน 3 แตะจริง (เปิด → เลือกผล → บันทึก) มีเทสต์นับแตะ
- ผลการโทรทั้ง 6 แบบ map ไปสถานะติดตามถูกต้อง มี unit test ครบทุกแบบ
- นัดครั้งถัดไปแบบลัดใช้ได้ · ระบุวันย้อนหลังได้ · ไทม์ไลน์เรียงตามเวลาที่เกิดจริง
- ตามได้ไม่จำกัดครั้ง — unit test โทร 20 ครั้งแล้วยังคำนวณถูก (ชีทเดิมตันที่ 6)
- ปิดเคสแล้วสถานะเปลี่ยนและปุ่มปิดหายไป
- unit 29/29 · e2e 18/18 · typecheck · lint · build ผ่าน
- `db:verify` ยังตรงกันหมดหลังมีเหตุการณ์ 4 ชนิดในระบบ

## บั๊กจริงที่เทสต์จับได้ — กล่องไม่ปิดหลังบันทึก

เทสต์ที่บันทึกผลโทรสองครั้งติดล้ม เพราะ overlay ของกล่องค้างบังหน้าจอ
สาเหตุคือหลังบันทึกสำเร็จ กล่องไม่ปิดเอง **ในการใช้งานจริงผู้ใช้จะกดบันทึกซ้ำ
แล้วเกิดเหตุการณ์ซ้ำ** เทสต์แรกไม่เจอเพราะเปิดกล่องแค่ครั้งเดียว

แก้โดยให้ action คืน `{ ok: true }` แยกจาก `{}` ตอนยังไม่ส่ง แล้วปิดกล่อง + ขึ้น toast

**ครั้งแรกแก้ด้วย `useEffect` ซึ่ง lint ปฏิเสธ** (`react-hooks/set-state-in-effect`)
เปลี่ยนไปเรียก action เองใน `useTransition` แล้วจัดการผลลัพธ์ตรงนั้น สะอาดกว่าและไม่ต้องมี effect

## การตัดสินใจ

- **`ไม่รับสาย` → `กำลังติดตาม` ไม่ใช่ `ติดต่อไม่ได้`** เพราะไม่รับสายครั้งเดียวไม่ได้แปลว่าติดต่อไม่ได้
  การเลิกตามเป็นการตัดสินใจของคน ผ่านปุ่มปิดเคส ไม่ใช่ผลข้างเคียงของการโทร
- **ผลที่จบแล้วล้างวันนัดอัตโนมัติ** ไม่งั้นคนที่สมัครแล้วจะยังโผล่ในคิวโทร
- ปุ่มบันทึกเป็น `sticky bottom-0` อยู่ครึ่งล่างของจอ กดด้วยนิ้วโป้งได้
