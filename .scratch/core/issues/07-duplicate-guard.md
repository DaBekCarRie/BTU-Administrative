# 07: กันข้อมูลซ้ำ

**What to build:** ระบบเตือนตอนกำลังจะสร้างข้อมูลซ้ำ และรวมสองรายการที่เป็นคนเดียวกันได้
โดยประวัติไม่แตกเป็นสองเส้น (ข้อมูลเดิมมีชื่อซ้ำ 122 แถว เบอร์ซ้ำ 16 แถว)

**Blocked by:** 04

**Status:** done

- [x] กรอกเบอร์ที่มีอยู่แล้วขึ้นเตือนทันที พร้อมชื่อคนเดิมและลิงก์ไปดู
- [x] **เตือนแล้วยังบันทึกต่อได้ถ้าเจ้าหน้าที่ยืนยัน** — บางเบอร์ใช้ร่วมกันในครอบครัวจริง
- [x] หัวหน้าทีมรวมสองรายการเป็นคนเดียวได้
- [x] หลังรวม เหตุการณ์ของทั้งสองรายการอยู่ในไทม์ไลน์เดียว เรียงตามเวลาที่เกิดจริง
- [x] การรวมถูกบันทึกเป็นเหตุการณ์ ย้อนดูได้ว่าใครรวมเมื่อไหร่

## ผลการตรวจ

- กรอกเบอร์ซ้ำขึ้นเตือนพร้อมชื่อและลิงก์ แต่ยังบันทึกต่อได้
- รวมสองรายการแล้วประวัติทั้งสองมาอยู่ในไทม์ไลน์เดียว เรียงตามเวลาจริง
- รายการที่ถูกรวมหายจากรายชื่อ · การรวมบันทึกเป็นเหตุการณ์ `รวมข้อมูล`
- e2e 25/25 · unit 34/34 · typecheck · lint · build ผ่าน

## พฤติกรรมผิดที่เจอ — รวมแล้วชื่อกลายเป็นของอีกฝั่ง

ตอนเล่นเหตุการณ์ซ้ำหลังรวม `ติดต่อเข้ามา` ของรายการที่ถูกรวมซึ่งเกิดก่อน มาก่อน
รายการที่เหลือรอดจึงถูกเปลี่ยนชื่อเป็นของอีกฝั่ง

แก้โดยให้เหตุการณ์ `รวมข้อมูล` **พกข้อมูลของรายการที่เหลือรอดไปด้วย**
และเป็นเหตุการณ์สุดท้ายเสมอ ข้อมูลที่ถูกต้องจึงชนะ มี unit test ตรึงไว้ 2 เคส

## บั๊กจริงอีกข้อ — เหตุการณ์ "วันนี้" ถูกตั้งเป็นเวลาอนาคต

เดิมแปลงวันที่จากฟอร์มเป็นเที่ยงวันเสมอ ถ้าบันทึกตอนเช้าจะได้เวลาอนาคต
รายการนั้นจะเรียงขึ้นเหนือสิ่งที่เพิ่งเกิดจริง ทำให้ lead ที่เพิ่งสร้างไม่อยู่หน้าแรก
แก้เป็น: เลือกวันนี้ใช้เวลาปัจจุบัน เลือกวันอื่นค่อยใช้เที่ยงวันของวันนั้น

## ปรับปรุงชุดเทสต์

- **ล็อกอินครั้งเดียวแล้วใช้ session ร่วมกัน** (Playwright storageState)
  เดิมทุกเคสล็อกอินเอง 22 ครั้งต่อรอบ จน Supabase Auth rate limit แล้วเทสต์ล้มเป็นชุด
- ล้างข้อมูลทดสอบที่สะสม 120 รายทิ้ง ฐานข้อมูลสะอาดก่อนทำใบ 15
- เทสต์หา lead ผ่านการค้นหา ไม่พึ่งว่าจะอยู่หน้าแรก

## การตัดสินใจ

- `merge_people()` เป็น `security definer` เพราะตาราง `events` ตั้งใจให้แก้ไม่ได้
  การย้ายเจ้าของเหตุการณ์เป็นข้อยกเว้นเดียว และทำได้ทางฟังก์ชันนี้ทางเดียว
- จำกัดให้**หัวหน้าทีมเท่านั้น**ที่รวมได้ เพราะย้อนกลับไม่ได้
- เอกสารมี unique (คน, ประเภท) จึงย้ายเฉพาะประเภทที่ปลายทางยังไม่มี
