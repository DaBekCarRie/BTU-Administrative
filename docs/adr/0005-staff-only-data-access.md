# เฉพาะเจ้าหน้าที่ที่ยังใช้งานอยู่จึงอ่านข้อมูลได้

policy ของทุกตารางใช้เงื่อนไข **"มีแถวเจ้าหน้าที่ที่ยังใช้งานอยู่"** ไม่ใช่ "ล็อกอินแล้ว"
คนที่ล็อกอินได้แต่ไม่ใช่เจ้าหน้าที่ อ่านได้ศูนย์แถวทุกตาราง ทุก view และทุกไฟล์

## ทำไม (อย่าคิดว่าข้อนี้ขัด ADR-0004)

ADR-0004 เขียนว่า policy คือ "ผู้ใช้ที่ล็อกอินแล้วเห็นได้" และ "ความต่างอยู่ที่**คนนอกยังเข้าไม่ได้เลย**"
สองประโยคนั้นจริงพร้อมกันได้เพราะตอนนั้นบัญชีทุกบัญชีถูกสร้างด้วยมือ ล็อกอินได้เท่ากับเป็นเจ้าหน้าที่

พอเปิดลงชื่อเข้าใช้ด้วย Google ใครก็สมัครแล้ว "ล็อกอินแล้ว" ได้ทันที ประโยคแรกเลยไปทำลายประโยคที่สอง
พิสูจน์บนฐานข้อมูลจริง (12 ก.ย. 2569): ผู้ที่ล็อกอินแต่ไม่มีแถวเจ้าหน้าที่อ่านได้คน 3,434 ราย
เหตุการณ์ 6,497 รายการ เอกสาร 52 และการชำระเงิน 27 รายการ

**ข้อนี้รักษาเจตนาของ ADR-0004 ไว้** — เจ้าหน้าที่ทุกคนยังเห็นและแก้ทุกอย่างเหมือนเดิม
ไม่มีการกั้นระหว่างเจ้าหน้าที่ด้วยกัน เส้นแบ่งเดียวที่เพิ่มคือเจ้าหน้าที่กับคนนอกทีม

## ทำไมต้องกันที่ฐานข้อมูล ไม่ใช่ในแอป

แอปมีด่านอยู่แล้วสองจุด (callback ของ OAuth และ layout) แต่กันได้แค่หน้าจอ
- route handler ไม่วิ่งผ่าน layout หน้าส่งออกไฟล์จึงเปิดโล่ง
- คนถือ token ยิง API ของ Supabase ตรง ๆ ข้ามแอปทั้งก้อน policy คือด่านเดียวที่เหลือ

## ทางเลือกที่ไม่เลือก

- **กันแค่ในแอป** — ปิดประตูหน้าแต่ประตูหลังยังเปิด
- **จำกัดโดเมนอีเมลของ Google** — Google ไม่ได้ส่งค่าโดเมนมาทุกกรณี และอีเมลของทีมบางคนเป็น Gmail ส่วนตัว
- **ปิดการสมัครบัญชีใหม่อย่างเดียว** — ทำด้วย (บน Dashboard) แต่เป็นการตั้งค่าที่เปิดกลับได้ง่าย
  ถ้าวันหนึ่งมีคนเปิดชั่วคราวแล้วลืมปิด ข้อมูลต้องยังปลอดภัย

## ผลที่ตามมา

- policy ใหม่ทุกตัวต้องใช้ `(select private.current_staff_id()) is not null` ห้ามใช้ `true`
- ปิดการใช้งานเจ้าหน้าที่ (`is_active = false`) ตัดสิทธิ์อ่านข้อมูลทันที
- migration `20260913074940_staff_only_access`
