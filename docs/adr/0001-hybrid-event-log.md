# เก็บเป็นบันทึกเหตุการณ์ควบคู่กับสถานะปัจจุบัน

งานของทีมคือการเปลี่ยนสถานะคนซ้ำไปมาข้ามเทอม — ย้ายเทอม ดรอป กลับมาเรียน
ลาออกแล้วสมัครใหม่ — และเคยเสียประวัติไปเพราะระบบเดิมเขียนทับค่าเดิมในชีท
เราจึงเก็บทุกอย่างเป็น **เหตุการณ์ที่เพิ่มอย่างเดียว** (`events`) เป็นแหล่งความจริง
แล้วเก็บสถานะปัจจุบันที่คำนวณไว้แล้วไว้ในตาราง `people` ควบคู่ไปด้วย

## เหตุผลที่ไม่เลือกทางอื่น

**ไม่เลือกคอลัมน์สถานะอย่างเดียว** เพราะจะเขียนทับประวัติ และตอบไม่ได้ว่า
"เทอมที่แล้วคนนี้สถานะอะไร" ซึ่งทีมต้องใช้จริงเวลาคุยกับสำนักทะเบียน

**ไม่เลือก event sourcing เต็มรูปแบบ** เพราะโปรเจกต์นี้ให้ AI เขียนโค้ดเป็นหลัก
และ AI เขียน event sourcing ผิดบ่อย — การ query ผ่าน projection อย่างเดียว
จะทำให้หน้าจอธรรมดากลายเป็นงานยากโดยไม่จำเป็น

## ผลที่ตามมา

- หน้าจอทั่วไปอ่านจาก `people` · หน้าประวัติอ่านจาก `events`
- `people` เป็นข้อมูลที่คำนวณได้ — ถ้าเพี้ยน ต้องสร้างใหม่จาก `events` ได้เสมอ
- การแก้ข้อมูลที่บันทึกผิดต้องออกเหตุการณ์แก้ ไม่ใช่ลบของเดิม
- "ใครบันทึก เมื่อไหร่" ติดมากับทุกเหตุการณ์โดยอัตโนมัติ

## ข้อยกเว้น: ถอดข้อมูลส่วนบุคคลออกทั้งชุด (13 ก.ย. 2569)

"ไม่ลบไม่แก้" ใช้กับการแก้ข้อมูลที่บันทึกผิด ไม่ได้ห้ามการถอดข้อมูลคนออกจากระบบทั้งชุด
เช่นใบ `lockdown-and-extensions/04` ที่แทนข้อมูลจริงด้วยข้อมูลสมมติ ทำได้เมื่อ

- ลบทั้งคนพร้อมเหตุการณ์ทั้งหมดของคนนั้น (cascade จาก `people`) แล้วนำเข้าชุดใหม่ผ่าน `record_event()`
  **ห้ามเขียนทับ payload ของเหตุการณ์ที่เหลืออยู่** — ประวัติที่เหลือต้องเป็นของจริงเสมอ
- สำรองก่อนลบ (`npm run db:backup`) และรายงานจำนวนที่จะลบก่อนลงมือ (`npm run db:reset-to-mock`)
